01

概要

本仕様書は、サービスサイトに設置する お問い合わせフォーム の機能要件、画面挙動、API 連携、品質基準を定義する。送信内容は運営チームの受信箱へ転送され、送信者には自動返信メールが届く。

スコープ外

受信側の管理画面、SLA 設計、メールテンプレートのコピーライティングは別仕様書に分離する。

02

関係者

  • プロダクトオーナー（要件決定）
  • フロントエンド担当（画面実装）
  • バックエンド担当（API・メール配信）
  • カスタマーサポート（受信箱運用）
  • 法務（プライバシーポリシー文言）

03

ユースケース

  1. 未登録の訪問者がプロダクトに関する質問を送信する
  2. 既存ユーザーが不具合を報告する
  3. パートナーシップに関する問い合わせを送信する
  4. 取材・登壇依頼を送信する

04

画面構成

1 カラムの縦長レイアウト。最大幅は 720px。ヒーロー、フォーム本体、補助情報、送信完了画面の 4 ブロックから構成する。

ブロック

ヒーロー
ページタイトルと一文の説明、平均応答時間の表示。
フォーム本体
5 つの入力フィールドと送信ボタン。
補助情報
連絡先メールアドレス、営業時間、よくある質問へのリンク。
送信完了画面
送信成功時にフォームと置換。受付番号と次のアクションを案内。

06

バリデーション

クライアント側

HTML 標準属性（required / type / minlength / maxlength / pattern）で完結させる。JavaScript は補助のみ。

サーバ側

クライアント側と同条件に加え、スパムフィルタおよび reCAPTCHA v3（スコア ≥ 0.5）で再検証する。

エラー表示

エラーメッセージは入力欄の直下にインライン表示し、aria-describedby で関連付ける。送信時の要約は role="alert" でフォーム上部に出す。

07

画面状態

状態挙動
defaultすべての入力欄が編集可能。送信ボタンは活性。
submitting送信ボタンに spinner、入力欄を readonly、二重送信を抑止。
success送信完了画面に置換し、トラッキングイベントを発火。
errorエラー要約をフォーム上部に表示、最初の不正項目に focus を移す。

08

API 仕様

エンドポイント

POST /api/contact

リクエスト

{
  "name": "山田 太郎",
  "email": "taro@example.com",
  "topic": "question",
  "message": "...",
  "agreed_at": "2026-05-10T11:00:00+09:00",
  "recaptcha_token": "..."
}

レスポンス（成功）

HTTP/1.1 202 Accepted
Content-Type: application/json

{ "ticket_id": "TCK-20260510-0001" }

エラーステータス

  • 400 Bad Request — バリデーションエラー
  • 429 Too Many Requests — レート制限超過 / reCAPTCHA スコア不足
  • 5xx — サーバ側障害（リトライ可）

09

アクセシビリティ

WCAG 2.2 AA に準拠する。

  • すべての入力欄に対応する <label> を持つこと。
  • エラー時は aria-invalid="true" と aria-describedby を必ず設定する。
  • focus-visible は 2px solid #d97757、offset 3px。
  • キーボードのみで全操作が完結すること。Tab 順序は視覚的順序と一致する。
  • 送信中・成功・失敗の状態を aria-live="polite" で通知する。
  • 本文と背景のコントラスト比は 4.5:1 以上を保つ。

10

QA チェックリスト

  • 必須項目が空のまま送信できないこと。
  • 不正なメール形式で送信を試みた際にインラインエラーが表示されること。
  • 送信中に再度送信ボタンを押下しても二重送信が発生しないこと。
  • バリデーションエラー後、最初の不正項目に focus が移動すること。
  • スクリーンリーダーで送信状態（送信中 / 成功 / 失敗）が読み上げられること。
  • reCAPTCHA スコアが閾値未満の場合に 429 が返ること。
  • WCAG 2.2 AA のコントラスト比を全テキストで満たすこと。
  • モバイル幅（375px）でレイアウト崩れがないこと。
