01

準拠目標

本サイトおよびすべてのコンポーネントは WCAG 2.2 レベル AA を満たすことを目標とする。

Standard
WCAG 2.2 AA
Web Content Accessibility Guidelines
Verification
手動 + 自動
axe-core / Lighthouse / NVDA / VoiceOver

02

コントラスト

本文 4.5:1 以上、大きい文字（18pt または 14pt 太字以上）と UI コンポーネント・グラフィックは 3:1 以上を満たすこと。

サンプル

本文テキスト on Raised surface
15.9 : 1本文 / AA
補助テキスト on Raised surface
10.6 : 1本文 / AA
アクセント色 on Raised surface
3.4 : 1大文字のみ / AA Large
Inverse on Raised surface
2.7 : 1本文不可 / FAIL

color.text.inverse は本文には使えない。eyebrow / メタ情報など装飾的な用途のみ。

03

キーボード操作

マウス操作なしですべての機能が完結すること。

キー挙動
Tab次のフォーカス可能要素へ移動
Shift + Tab前のフォーカス可能要素へ移動
Enterリンク・ボタンを実行
Spaceボタン実行 / チェックボックス切り替え
Escモーダル / ポップオーバーを閉じる
↑ ↓セレクトメニュー / リストの選択移動

ルール

  • Tab 順序は視覚的な順序と一致させる。tabindex 正の値は使わない。
  • キーボードでフォーカスできない要素にクリックハンドラを付与しない。
  • キーボードトラップ（フォーカスが外れない状態）を作らない。

04

focus-visible

フォーカスインジケータは 常に視認可能 でなければならない。outline: none 単独での消去は禁止。

仕様

  • 太さ 2px solid
  • 色 color.text.tertiary (#d97757)
  • offset 3px
  • radius は対象要素に合わせる（リンクは 4px、ボタンは radius.sm）

サンプル

フォーカス中のボタン 
:focus-visible {
  outline: 2px solid var(--color-text-tertiary);
  outline-offset: 3px;
}

05

ARIA

セマンティック HTML を最優先し、ARIA は HTML だけで表現できない場合の補強 として使う。

使用ルール

属性用途
aria-label視覚ラベルがないアイコンボタン等の名前付け
aria-describedby入力欄とエラーメッセージの関連付け
aria-invalid="true"バリデーション不通過の入力欄
aria-live="polite"送信状態など非同期メッセージの通知
aria-expanded開閉可能なディスクロージャ要素の状態
role="alert"送信失敗など即時通知が必要なメッセージ

禁則

  • div や span に role="button" を付けず、<button> を使う。
  • セマンティック HTML と矛盾する role は付けない。

06

スクリーンリーダー

NVDA（Windows）と VoiceOver（macOS / iOS）を主要対象として確認する。

確認ポイント

  • すべての画像に alt 属性を付ける。装飾画像は alt=""。
  • 見出しレベル（h1 → h2 → h3）の飛ばしをしない。
  • ランドマーク（header, main, nav, footer）を適切に配置する。
  • フォームの送信中・成功・失敗を aria-live 領域に出力する。
  • 状態の変化（バッジの色変更など）はテキストでも伝える。

07

モーションと縮小設定

prefers-reduced-motion が reduce の場合、装飾的なアニメーションを停止する。

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
  • 状態フィードバックに必要な遷移（focus / hover の色変化）は維持してよい。
  • 視差スクロール・自動再生動画は停止または非表示にする。

08

QA チェックリスト

  • キーボードのみで全ページの主要操作を完了できる。
  • すべてのフォーカス可能要素に視認可能な focus-visible が出る。
  • 本文と背景のコントラスト比が 4.5:1 以上ある。
  • すべての入力欄に対応する <label> がある。
  • エラー時に aria-invalid と aria-describedby が設定されている。
  • 非同期の状態変化（送信中 / 成功 / 失敗）が支援技術に伝わる。
  • 見出しレベルがスキップされていない。
  • prefers-reduced-motion 設定時に装飾アニメーションが停止する。
  • axe-core / Lighthouse の自動チェックでエラー 0 件。
  • NVDA または VoiceOver で実際に主要フローを通せる。
